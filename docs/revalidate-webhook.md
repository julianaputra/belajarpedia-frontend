# Revalidate Webhook — Backend Integration Contract

**Audience:** Laravel backend team (Belajarpedia API).
**Purpose:** Trigger on-demand ISR cache invalidation on the Next.js frontend
after any data write that affects user-visible pages.
**Spec ref:** `docs/implementation_plan_frontend.md` §6.5 + OpenAPI
`/internal/revalidate` (T-02 risk mitigation).

---

## Endpoint

| Env | URL |
|---|---|
| Local | `http://localhost:3000/internal/revalidate` |
| Staging | `https://staging.belajarpedia.com/internal/revalidate` |
| Production | `https://belajarpedia.com/internal/revalidate` |

**Method:** `POST`
**Content-Type:** `application/json`
**Auth header:** `X-Revalidate-Secret: <shared-secret>`

The secret is the same string on both sides:
- Frontend: `REVALIDATE_SECRET` env var (server-side, never exposed)
- Laravel: matching `REVALIDATE_SECRET` env var

Use a long, random string (≥32 chars). Rotate quarterly.

## Request Body

```json
{
  "paths": [
    "/sekolah/bali/kab-badung/kuta-utara/negeri/smp-negeri-2-kuta-utara",
    "/sekolah/bali/kab-badung/kuta-utara/negeri",
    "/sekolah/bali/kab-badung/kuta-utara",
    "/sekolah/bali/kab-badung",
    "/sekolah/bali"
  ],
  "tags": ["facility:sekolah:smp-negeri-2-kuta-utara"]
}
```

- **`paths`** — array of literal URL paths (must start with `/`, max 1024 chars
  each, max 100 entries per request). Each path's ISR cache is invalidated;
  the next visitor triggers a fresh server render.
- **`tags`** — array of cache tag strings (max 256 chars, max 100 entries).
  We tag fetches with patterns like `facilities:sekolah` (all sekolah lists),
  `facility:sekolah:{slug}` (a specific detail), `facilities:universitas`, etc.
  Calling `revalidateTag("facilities:sekolah")` invalidates every list across
  all hierarchical levels in one call.

At least one of `paths` or `tags` must be non-empty.

## Response

```json
{
  "revalidated": {
    "paths": ["/sekolah/bali/...", "..."],
    "tags": ["facility:sekolah:..."]
  },
  "skipped": []
}
```

| Status | Meaning |
|---|---|
| 200 | Revalidation triggered. Body lists what was processed. |
| 400 | Bad JSON, or both `paths` and `tags` empty. |
| 401 | Missing/wrong `X-Revalidate-Secret`. |
| 405 | Wrong method (only POST is accepted). |
| 503 | `REVALIDATE_SECRET` not configured on the Next.js host (deploy issue). |

## Event → Paths Mapping

Per Decision §6.5. Send these paths whenever the corresponding write happens.

### Sekolah CRUD / score / status change

```php
$paths = [
    "/sekolah/{$provinsi}/{$kabkota}/{$kecamatan}/{$schoolType}/{$slug}", // detail
    "/sekolah/{$provinsi}/{$kabkota}/{$kecamatan}/{$schoolType}",        // leaf list
    "/sekolah/{$provinsi}/{$kabkota}/{$kecamatan}",                      // kecamatan
    "/sekolah/{$provinsi}/{$kabkota}",                                    // kabkota
    "/sekolah/{$provinsi}",                                               // provinsi
    "/sekolah",                                                           // root
];
$tags = ["facility:sekolah:{$slug}", "facilities:sekolah"];
```

### Universitas CRUD / score / status change

```php
$paths = [
    "/universitas/{$provinsi}/{$kabkota}/{$kecamatan}/{$slug}",
    "/universitas/{$provinsi}/{$kabkota}/{$kecamatan}",
    "/universitas/{$provinsi}/{$kabkota}",
    "/universitas/{$provinsi}",
    "/universitas",
```

```php
$paths = [
```

### Facility status=removed

Same paths as above. The detail endpoint's next render will see `status=removed`
on the API and emit the 410 Gone UI (AC-03).

### Review delete by admin (AC-24)

```php
$paths = [
    /* the affected facility's detail + parent list URLs, same shape as CRUD */
];
$tags = ["facility:{$category}:{$slug}"];
```

### Kursus category disable/delete

```php
$paths = ["/kursus", "/"];   // home + kursus root
$tags = ["facilities:kursus"];
```

### Daily sitemap regen (scheduler)

Sitemaps are generated by `app/sitemap.ts` and per-category nested ones. They
honor `revalidate: 3600` already; if you want to flush mid-day:

```php
$paths = ["/sitemap.xml", "/sekolah/sitemap/0.xml", "/universitas/sitemap/0.xml", "/kursus/sitemap/0.xml"];
```

## Laravel Implementation Sketch

```php
// app/Jobs/RevalidateRoutesJob.php
class RevalidateRoutesJob implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable;

    public int $tries = 3;
    public array $backoff = [10, 60, 300]; // seconds

    public function __construct(
        public array $paths = [],
        public array $tags = [],
    ) {}

    public function handle(): void
    {
        $url    = config('services.frontend.revalidate_url');
        $secret = config('services.frontend.revalidate_secret');

        $response = Http::withHeaders(['X-Revalidate-Secret' => $secret])
            ->timeout(10)
            ->post($url, [
                'paths' => array_values(array_unique($this->paths)),
                'tags'  => array_values(array_unique($this->tags)),
            ]);

        if (!$response->successful()) {
            Log::warning('Revalidate webhook failed', [
                'status' => $response->status(),
                'body'   => $response->body(),
            ]);
            $this->release($this->backoff[$this->attempts() - 1] ?? 300);
        }
    }
}
```

Dispatch from your `FacilityObserver`/Score-recalc service after the DB
transaction commits.

## T-02 Acceptance Test

To prove the webhook works end-to-end before launch:

1. Visit a detail page (e.g. `/sekolah/bali/kab-badung/kuta-utara/negeri/smp-negeri-2-kuta-utara`).
   Note the `Last verified` date or any other server-rendered field.
2. Update that facility from Filament admin (e.g. change description).
3. The score-recalc/observer dispatches a `RevalidateRoutesJob`.
4. Refresh the public detail page within 5 seconds.
5. **Pass:** the new description shows up. **Fail:** old description persists
   (cache wasn't invalidated).

Wire this as a Playwright E2E test in Phase 11.

## Verification Curl

Local sanity check after deploy:

```bash
curl -i -X POST https://belajarpedia.com/internal/revalidate \
  -H "Content-Type: application/json" \
  -H "X-Revalidate-Secret: $REVALIDATE_SECRET" \
  -d '{"paths":["/sekolah/bali"], "tags":["facilities:sekolah"]}'
```

Expected: `200 OK` + JSON listing the revalidated entries.

Wrong secret should return `401 {"error":"Unauthorized"}` regardless of body.

## Security Notes

- Secret comparison is timing-safe on Next.js side (constant-time compare).
- The endpoint is **not** rate-limited at the framework level. If exposed
  publicly, ensure Cloudflare WAF / firewall blocks anything except known
  Laravel egress IPs. In private network deployments this is moot.
- Logs from the route handler include path summary; never log secrets or
  request body to files.
